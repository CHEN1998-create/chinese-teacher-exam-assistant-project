# PRD v6.1：基于现有仓库的分模块改造提示词

适用项目：全国教师公开招聘与备考助手  
目标阶段：可演示、可供少量受邀用户试用的验证版，不按正式生产规模建设  
使用方式：先执行“共用总提示词”，再按模块 0→0A→1→2→…→9 顺序逐个执行。每个模块单独开一轮，验收通过后再进入下一模块，不要一次让编码智能体改完整个项目。

---

## 1. 目标澄清

**原始目标**：根据 PRD v6.1、前文确定的轻量技术方案和简洁高效的页面布局，基于现有 GitHub 仓库，形成分模块、可直接交给编码智能体执行的修改提示词。

**显性目标**：把当前 v5.2“先确定考试、再安排今天任务”的演示原型，迁移为 v6.1“机会发现 → 资格解释 → 关注与日程 → 主要目标 → 备考”的演示产品。

**隐性目标**：避免推倒重写和功能堆砌，让每个模块都能独立交付、验证和回退；同时让代码、README、PRD、部署说明保持一致。

**核心目标**：在保留现有可复用能力的前提下，用最少的新增基础设施跑通 v6.1 的一条可信闭环。

### 当前已知上下文

| 项目 | 当前状态 |
|---|---|
| 产品需求 | 根目录已有 `PRD-全国教师公开招聘与备考助手-v6.1.md` |
| 技术研究 | 已有 `docs/PRD-v6.1-技术可行性与开发方案.md` 和 `docs/technical-feasibility-sources.md` |
| 前端 | Next.js 16、React 19、TypeScript、Tailwind CSS 4 |
| 后端 | NestJS 12、Prisma 6、PostgreSQL，目前仅有骨架和健康检查 |
| 数据 | 主要为浏览器 `localStorage` Mock |
| 测试 | 前端 41 个用例通过；后端基础测试通过 |
| 当前信息架构 | “今天 / 7 天 / 我的考试”，仍是 v5.2 口径 |
| 当前阶段 | 少量受邀用户验证，不追求全国自动化和生产级扩展 |
| 网络约束 | 少量受邀用户必须能在中国大陆普通网络直接打开和使用，不以 VPN/代理为前提 |

### 暂定决策

- 保留 Next.js 前端和 NestJS 单体后端，不迁移框架、不拆微服务；仓库已有 API 代理、Prisma 和部署基础，继续使用比搬入 Next.js 更少改动。
- PostgreSQL 作为共享事实库；访客体验可继续使用 `localStorage`，公共机会、公告版本、审核数据和登录用户数据逐步迁到后端。
- 首版不引入 Redis、BullMQ、Kafka、Elasticsearch、向量数据库、Kubernetes和自动全国爬虫。
- 公告数据首版由管理员手动提交链接/文件，机器提取后人工审核，再发布版本。
- 用户端主导航只保留“机会 / 日程 / 备考”。
- AI 只生成候选提取和辅助文案，不直接作出资格结论。
- 受邀试用环境部署在中国大陆可稳定访问的云服务上；前端运行时不得依赖 Google Fonts、境外 CDN、Vercel、Firebase、Supabase 或其他需要代理才能稳定访问的服务。浏览器统一访问同源 `/api/*`，第三方服务由后端调用。

### 仍需以后用真实数据确认

| 问题 | 当前处理方式 |
|---|---|
| 首批覆盖地区 | 先使用 3—5 个有代表性的示例地区 |
| 首批真实公告数量 | 建议 30—50 份，代码先支持 Mock 与人工导入 |
| 受邀用户数量 | 暂按 5—30 人设计 |
| 是否启用真实账号 | 最后单独执行“受邀账号与持久化”模块 |
| 是否发送短信/微信提醒 | 本轮不做，用站内提醒验证需求 |

```text

工作规则：
- 先检查现有实现和测试，再修改；保留用户已有代码和无关改动。

- 领域规则集中在 domain 层，页面只负责展示和交互。
- 正式状态不允许静默回退到 Mock；演示数据必须明确标识。
- 新增状态必须覆盖成功、加载、空数据、失败和权限不足。
- 修改后运行相关测试、类型检查、lint 和构建；构建及运行时不得再依赖 Google Fonts 或境外 CDN，不能只记录失败后跳过。
- 完成时报告：修改文件、关键决策、验证命令与结果、剩余风险。
```

## 4A. 模块 0A：建立国内普通网络可访问基线

```text
请执行“国内普通网络可访问基线”模块。本轮先消除会导致用户必须使用 VPN/代理的运行依赖，并补齐轻量部署说明；不要开始实现 v6.1 产品功能。

目标：让少量受邀用户可以在中国大陆普通家庭宽带和手机网络中打开核心页面、登录并调用 API。这里的“可访问”不仅是把服务器放到国内，还包括页面加载过程中不存在被阻断的境外字体、脚本、图片、接口、AI/OCR 或存储依赖。

重点检查：
- `frontend/src/app/layout.tsx`
- `frontend/src/app/globals.css`
- `frontend/next.config.ts`
- `frontend/src/app/api/[...path]/route.ts`
- `frontend/package.json` 和 `frontend/public/`
- `frontend/DEPLOYMENT.md`
- `backend/src/main.ts`
- 仓库内所有运行时 URL、字体导入、CDN 地址和第三方 SDK
- 部署配置和环境变量名称；不要读取、输出或提交任何真实密钥

需要完成：
1. 建立运行时外部依赖清单，区分：产品必要依赖、仅供用户点击的官方公告链接、开发/构建期依赖。把允许的运行时域名记录到 `docs/china-network-accessibility.md`。
2. 移除 `next/font/google`、Google Fonts 和境外字体 CDN。优先使用系统中文字体栈；确有品牌字体需求时，把有授权的字体文件放入本地静态资源并用 `next/font/local`。
3. 图标、关键图片、脚本和样式随应用部署，不从 GitHub Raw、unpkg、jsDelivr 或其他境外 CDN 运行时加载。普通官方公告外链可以保留，但外链失败不能导致产品页面不可用。
4. 浏览器统一通过同源 `/api/*` 访问服务。Next.js 服务端代理再访问 NestJS 的内网地址或同机地址，前端不得直接请求内网 IP、境外 API 或携带第三方密钥。
5. 在 `frontend/DEPLOYMENT.md` 增加“少量受邀用户国内部署”方案：一台境内云服务器运行 Next.js、NestJS 和反向代理；PostgreSQL 与对象/文件存储选择同地区境内服务。不要为了 5—30 人引入 Kubernetes、微服务或多地域容灾。
6. 部署拓扑保持单域名：`https://产品域名/` 到 Next.js，`https://产品域名/api/*` 反向代理到 NestJS。启用 HTTPS；数据库、后台管理端口和对象存储密钥不暴露给公网浏览器。
7. 如果后续接入 AI/OCR，先定义后端 Provider 接口；受邀环境只配置在中国大陆可直接访问且数据条款可接受的供应商。供应商不可用时，回退为人工录入/人工审核，而不是让核心页面白屏。
8. 根据真实依赖收紧 CSP：默认同源，只增加经过确认的境内地址；不要继续使用笼统的 `https:` 允许所有图片或连接来源。
9. 在文档中明确：部署到中国大陆公开域名通常需要按云服务商和主管部门要求完成 ICP 备案，并配置可用域名、DNS 和 HTTPS。在备案完成前只做本地或内部演示，不编写绕过方案。
10. 增加可重复执行的网络依赖检查，列出构建产物和页面运行时实际访问的外部 origin；测试必须能发现重新引入 Google Fonts 或境外 CDN。

验证场景：
- 在没有代理的中国大陆家庭网络和手机网络分别打开首页、登录页、机会页、管理登录页和 API 健康检查；
- 浏览器网络面板中，核心流程只出现同源请求和允许清单内的境内地址；
- 干净构建不再因访问 `fonts.googleapis.com` 或 `fonts.gstatic.com` 失败；
- 禁止境外第三方请求后，核心页面仍能加载、登录、显示本地素材并调用 API；
- 官方公告外链打不开时，只提示“暂时无法打开来源”，不影响查看已经审核并保存的公告信息；
- 前端源码、构建产物和浏览器网络请求中没有服务端密钥。

验收输出：
- 修改文件和删除的境外运行时依赖；
- 一份运行时允许域名清单；
- 一张简短部署拓扑说明；
- 构建结果和两种普通国内网络的实际访问记录；
- 尚未完成的 ICP、域名或云资源前置事项，不能把未实测状态写成“国内可用”。
```

## 5. 模块 1：建立 v6.1 领域模型和演示数据

```text
请执行“v6.1 领域模型与演示数据”模块。本轮建立类型、纯领域规则和 Mock 数据，不修改导航，不接真实数据库接口。

目标：让代码能准确表达招聘公告、报考单元、用户画像、资格匹配、关注状态和主要目标，同时保留现有备考计划能力。

先检查：
- `frontend/src/types/index.ts`
- `frontend/src/lib/mock-data.ts`
- `frontend/src/lib/targets/`
- `frontend/src/lib/evidence/`
- `frontend/src/lib/governance/`
- 相关测试

需要新增或调整的核心概念：
- RecruitmentAnnouncement：招聘公告；
- AnnouncementVersion：公告版本；
- ApplicationUnit：用户实际报名的报考单元；
- EmploymentNature：事业编、备案制、员额制、控制数等官方名称；
- AllocationMethod：直接报学校、按成绩择校、统一调配；
- Requirement：学历、学位、专业、身份、教师资格、年龄、户籍、社保、经历和其他条件；
- EvidenceAnchor：URL、文件、页码、工作表、单元格、原文片段；
- UserRecruitmentProfile：五组基础画像和按需补充条件；
- MatchDimensionResult：PASS、FAIL、UNKNOWN、MANUAL_REVIEW；
- OpportunityMatchResult：初步符合、补充信息后判断、建议人工确认、明确不符合；
- FollowStatus：考虑中、准备报名、已报名、已放弃、已结束；
- StudyTargetRole：主要目标、备选目标。

实现要求：
1. 将新类型按领域拆分到 `frontend/src/lib/opportunities/`、`profile/`、`matching/` 等目录，避免继续扩大 `types/index.ts`；跨模块公共类型再从统一入口导出。
2. 保留现有 `plans`、`materials`、`evidence` 代码，使用兼容层逐步迁移，不一次删除旧类型。
3. 编写纯函数匹配骨架：
   - 任一硬条件 FAIL → 明确不符合；
   - 无 FAIL 且有 MANUAL_REVIEW → 建议人工确认；
   - 无前两者且有 UNKNOWN → 补充信息后判断；
   - 所有关键条件 PASS → 初步符合；
```

## 6. 模块 2：可信公告数据流水线和审核后台

```text

- EvidenceAnchor：字段、页码/工作表/单元格/原文片段。

8. 用户端和匹配模块只能读取 published 版本。
9. 正式环境的权限在 NestJS 服务端校验，前端隐藏按钮不作为权限控制。

首版执行方式：数据库任务表 + 管理员手动点击处理即可；不做定时调度。若解析耗时，允许单独 Node Worker 轮询任务表，但不要引入新基础设施。

测试要求：
- 重复文件不生成重复快照；
- 未审核候选不能发布；
- 无证据的高影响字段不能通过；
- 人工修改前后均留痕；
- V2 发布不覆盖 V1；
- 失败任务可重试且不会重复发布。

验收标准：使用一份 HTML 公告和一份 Excel/PDF 附件，能完整走通提交、提取、审核、发布、查看 V1/V2 差异。
```

```text
模块 0 文档基线
    ↓

    ↓
模块 1 领域模型
    ↓
模块 2 可信数据流水线
    ↓
模块 3 信息架构与导航
    ↓
模块 4 画像与预览
    ↓
模块 5 匹配与关注
    ↓
模块 6 日程
    ↓
模块 7 备考
    ↓
模块 8 受邀账号
    ↓
```

模块 0A 必须在产品功能改造前完成，否则后面每个页面都可能重新带入境外依赖。模块 2 的后台界面和模块 3 的用户端骨架可以在不同分支并行，但合并前必须以模块 1 的领域模型为共同基础。模块 4—7 建议串行，避免同时修改路由、类型和 Mock 数据造成冲突。

## 15. 主要风险与验收清单

### 风险

| 风险 | 影响 | 预防方式 |
|---|---|---|
| 一次让智能体完成全部模块 | 大范围重写、难以 review | 每轮只发一个模块提示词 |
| 文档先声称能力已完成 | 测试用户误解 | README 明确 current/target |
| 新旧领域模型一次性替换 | 现有 41 个测试和计划逻辑失效 | 兼容层迁移，最后清理 |
| UI 重构时增加更多卡片 | 再次形成信息堆砌 | 每页一个问题、一个主行动 |
| AI 提取直接发布 | 高影响事实错误 | 候选、审核、发布三态分开 |
| 后端复杂度过早膨胀 | 拖慢验证 | 不加消息队列、搜索集群和微服务 |
| Mock 与真实模式混用 | 数据不可信 | 环境模式明确，正式试用不得静默回退 |
| 境外运行时依赖导致必须翻墙 | 用户打不开、字体或接口长时间等待 | 境内部署、资源本地化、同源 API、允许域名清单和真实网络冒烟测试 |
| 服务器在国内但备案或域名未就绪 | 无法对外稳定提供访问 | 把 ICP、域名、DNS、HTTPS 作为部署前置事项，完成前仅内部演示 |
| 境外 AI/OCR 或存储服务中断 | 提取失败或核心页面不可用 | 第三方只由后端调用，境内服务优先，失败回退人工流程 |

### 最终验收清单

- [ ] 文档明确区分当前实现与 v6.1 目标；
- [ ] 用户端只有机会、日程、备考三个主入口；
- [ ] 每个首屏只有一个主行动；
- [ ] 公告机器提取必须经过人工审核才能发布；
- [ ] 每个高影响字段能追溯到原文证据；
- [ ] 公告历史版本不可被覆盖；
- [ ] 匹配支持四种结果，缺失信息不会变成不符合；
- [ ] 未登录可以看到初步结果，关注时再登录；
- [ ] 关注机会可以生成报名日程；
- [ ] 只有确认主要目标后才能进入精确备考计划；
- [ ] 原有计划、反馈和重排核心测试保持有效；
- [ ] 少量受邀账号之间数据隔离；
- [ ] README、部署说明和实际代码保持一致；
- [ ] 首页、登录、机会、日程、备考、管理审核和 API 可在中国大陆普通家庭网络与手机网络中无代理访问；
- [ ] 核心流程没有 Google Fonts、境外 CDN 或浏览器直连境外服务；
- [ ] 运行时允许域名清单、同源 API、HTTPS 和 ICP 前置事项已记录并按实际状态验收；
- [ ] 第三方服务失败不会让核心页面白屏，服务端密钥不会进入前端。
