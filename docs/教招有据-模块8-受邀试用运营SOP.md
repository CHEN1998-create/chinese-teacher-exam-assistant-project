# 教招有据 · 模块 8：受邀试用运营 SOP（每日记录、追访、人工对照与决策框架）

- 版本：v1.0（2026-10-06）
- 状态：**工具已交付，尚无真实受邀用户。** 邀请闸门见[模块 0—8 发布门槛总表](./教招有据-模块8-发布门槛总表.md)——门槛未全部通过前不得开始 D-3 招募；本文件所有报告模板保持空白，不预填、不编造结论。
- 适用：20—50 名目标用户、至少一个完整 7 日窗口的受邀试用。
- 上游口径：北极星与推进动作定义以[模块 0 决策记录](./教招有据-模块0-品牌清单与版本决策记录.md)第六节为唯一口径；产品取数以 `/admin/trial` 看板（服务端 `trial_events`）与机会供给卡片为准。

## 二、角色分工

| 角色 | 人数建议 | 职责 |
|---|---|---|
| 试用负责人 | 1 | 闸门核对、每日台账签字、决策报告执笔；有权暂停邀请 |
| 岗位维护人 | 1 | 官方栏目巡检、真实台账维护、供给卡片数据与交叉核对；**公告维护人时分开记** |
| 岗位复核人（exam_reviewer） | 1 | 高影响字段人工复核；高影响错误的复核关闭（门槛总表横切第 3 项，须指派到人） |
| 纠错处理人 | 1 | 处理用户纠错并回写结论；**当前系统无处理端点，属闸门缺项，闭环落地前不得开邀** |
| 追访人 | 1 | 未行动者名单触达、追访表登记（可与负责人同人） |

## 三、时间节奏

1. **D-3 ~ D-1 招募**：从模块 2 筛选问卷合格者与新招募中选 20—50 人；账号白名单逐个开通；告知「预筛、非官方、可退出」。建议分批（首批 10—15 人），首批 7 日窗口无阻断问题再放后续名额。
2. **D0**：账号激活、完成画像；当日确认事件在服务端可见（看板 invited 分群人数 +1）。**首个用户事件全链路不通则暂停发放新账号**，先修。
3. **D1—D7+ 每日**：固定时间抄录看板→每日指标台账；登记当日公告维护/复核/纠错人时；错误即记；滚动观察「观察中」人数。
4. **满窗口后 48h 内**：生成未行动者名单（第五节）并完成首次追访；失联者次日补一次，仍无应答记「失联」。
5. **窗口结束复盘**：至少一个完整 7 日窗口 + 20—50 人样本齐备后，按第六节出四选一决策报告；窗口或样本不齐只出「阶段性观察」，不出决策。

## 四、每日取数路径（看板 → 台账列）

**所有比率以看板为准，人工只抄数、不自行改口径；分母为 0 看板显示「—」，台账照抄「—」，不得写 0。**

| 台账字段 | 取数位置（invited 主列，除非注明） | 备注 |
|---|---|---|
| 在报岗位数 / 公告相位 / 来源失效 / 栏目失效 | 看板**机会供给卡片**（全局，不分分群） | 人工巡检登记值；交叉核对不一致时先排查，当日只可写「待排查」，**不得抄任一数定稿** |
| 累计受邀账号数 | 账号白名单（人工） | 看板 users 是有事件人数，不等于已发账号 |
| 当日活跃去重人数 | 服务端按日聚合查询（运维执行，不进浏览器） | 不开放给前端个人明细 |
| 画像各步 / 完成画像 | 漏斗区 profileSteps（5 步）+ 有效机会获得率分母 | **画像流失** = 上一步累计 − 本步累计，写当日台账「事件异常说明」或复盘，步间流失≥30% 要在复盘中单列 |
| 获得有效机会 / 依据理解 / 关注 / 补信息改判 / 材料 / 准备报名 / 入口 / 已报名 / 主要目标 | 漏斗区对应行的分子/分母 | 全部去重人数；各推进动作定义见模块 0 第六节 |
| 北极星分母/分子/率/观察中 | 北极星卡 | 未满 7 日只进「观察中」，永不提前入分母 |
| 满窗口未行动人数 | 北极星分母 − 分子（手算，与追访名单交叉一致） | — |
| 公告维护/复核/纠错**人时** | 人工自报，**无任何事件来源** | 按分钟记；换算「每个在报岗位维护人时」 |
| 高影响错误数 | 高影响错误台账当日计数 | 严重度口径沿用模块 2 第 5.4 节 |
| 事件缺失或异常说明 | 第六节对照流程的当日发现 | 无则写「无」 |

日终核对顺序：供给卡片交叉核对 → invited 分群抄数 → 人时汇总 → 错误台账对账 → 当日行签字。

## 五、未行动者追访 SOP

### 5.1 名单口径（由数据侧在受控环境生成，不向前端暴露个人行为）

1. **已满 7 日未推进**：北极星分母用户 − 分子用户（关注了但无有效推进、或根本未关注，两类在追访表「窗口状态」分开记）。
2. **未满 7 日不追访「没行动」**：窗口未到不构成结论；仅对主动反馈问题者即时响应。
3. **推进中断**：有过推进动作但超过 3 天无后续且过了报名截止的，列入关怀性追访（不计入未行动率分子口径，只做原因收集）。

### 5.2 触达与提纲（每次 ≤10 分钟）

1. 最近有没有看到合适的岗位？（供给事实核对）
2. 卡在哪一步：没关注 / 关注后没准备 / 材料 / 不敢进官方入口？（环节核对）
3. 对产品的结论信不信？为什么？——**无提示**让用户复述依据含义；若把「预筛」说成「官方保证/官方审核过」，按误认登记（红线指标）。
4. 有没有发现岗位信息不对、过期、对不上官网？（错误线索 → 纠错流程）
5. 下一步打算与约定时间。

零行动主因只用追访表固定枚举（无在报机会 / 等预告 / 个人时间 / 不信任 / 不会操作 / 材料困难 / 其他渠道已报名 / 其他），原话摘录另列；**先归因，再谈比例**。当前杭州/宁波 0 在报窗口下「已报名/进入入口」预期为 0，不得诱导用户对已截止批次做动作。

## 六、人工记录 × 事件数据对照（每周至少 1 次，窗口结束必做）

模块 2 的人工台账（人看到的）与 `/admin/trial`（事件算出的）是两套独立记录，必须逐人对账：

**对账方法**：抽取当批 ≥20% 用户（至少 5 人，含 2 名未行动者），把模块 2《7 日跟进表》中每人每天的动作，与服务端 `trial_events` 原始行（按 userId + occurredAt）逐条比对：动作有没有、时间是否在 7 日窗口内、去重是否符合预期、补信息是否真的导致结论变化。

**差异只允许归入三类，并分别处理——只展示比例、不解释差异的报告视为不合格：**

| 差异类别 | 典型现象 | 处置 |
|---|---|---|
| **样本不足** | 分母 < 计划下限（20 人）；误认子样本 <5；某环节分母为 0 | 该指标只描述人数、不报率、不下结论；决策报告标注「样本不足」，必要时延长招募，**不用百分比掩盖小样本** |
| **供给不足** | 用户没行动，但供给卡片显示当地 0 在报/预告中；有效机会获得率低且与画像无关 | 归为供给/时机问题，进入决策 B（收缩地区或人群/卡窗口期），不计产品失败；台账留供给证据 |
| **事件缺失/失真** | 人工确认做了动作但无事件（漏埋点、转发失败、被脱敏 400、去重误杀、跨设备丢失）；或事件有动作但用户说没做（误触发、账号串用） | 立即记[高影响错误台账](./教招有据-模块8-高影响错误台账.csv)（类型选「事件埋点缺失或重复计数」），修复前看板该指标标注「数据不完整」；**不得在修复前用该指标出决策** |

对账结论写入每日台账「事件缺失或异常说明」与决策报告附录；模块 2 人工访谈测得的依据复述率、误认率是**理解度的主证据**，事件侧 match_basis 率只证明「点开过依据」，二者不可互相替代。

## 七、决策报告框架（四选一；真实结果回来前保持空白）

### 7.1 前置条件（缺一不出决策）

- 邀请闸门全部 ✅；
- 20—50 人到组，且**至少一个完整 7 日窗口**结束；
- 人工×事件对照完成，事件缺失类差异已修复或明确标注；
- 高严重度错误有逐条处置状态。

### 7.2 四个选项与判据（阈值是待验证假设，复盘时先复核阈值本身；可带条件组合，不得无证据选择）

| 选项 | 同时满足的主条件 | 之后做什么 |
|---|---|---|
| **A. 继续聚焦资格判断** | 供给非瓶颈（在报岗位与画像匹配）；官方保证误认 <2 人且 <25%；高严重度错误已关闭；北极星偏低主要卡在「看不懂/不敢信判断」环节 | 留在资格判断核心迭代（依据表达、补信息引导、人工确认衔接），保持当前地区/人群再跑一个窗口 |
| **B. 收缩地区或人群** | 未行动主因以「无在报机会/等预告」为主，供给卡片与追访互证；或招募筛选显示人群画像普遍画不上 | 收缩到有在报批次的地区与窗口期（如 11—12 月批次），或更细分人群；**写明再放开条件**（地区/批次/人群信号） |
| **C. 先修数据与信任** | 误认触红线；或缺信息被当不符合等高危错误出现；或未复核/来源失效内容进入推荐；或事件缺失导致无法对账 | **立即停止扩量**，回模块 0/1/5/7 修复，对受影响用户重测通过后才重开；这是最高优先级选项，可覆盖其他结论 |
| **D. 再考虑 P0.5 与 P1（备考线）** | 北极星健康（对照模块 0 假设 ≥40% 先验证是否成立）、报考动作链通畅、样本足、供给可持续、无信任红线问题 | 才允许把学习计划/任务反馈等 P0.5/P1 提上议程；备考动作**仍不进北极星** |

### 7.3 扩量禁令

- **不因「接近目标」自动扩量**：阈值是待验证假设，38% vs 40% 不构成趋势证据；样本不足、窗口不完整、供给为 0 期间一律不扩量。
- 扩量必须由 A/D 结论 + 明确再验证计划（下一批人数、窗口、要复核的假设）共同支持；B/C 结论下只允许收缩或修复。

### 7.4 报告模板（真实数据回来前保持空白，不得预填）

1. **执行概况**：实际邀请/激活人数、分批节奏、日期窗口、完整 7 日窗口人数、失联人数与原因。
2. **机会供给**：每日在报岗位数曲线、相位变化、来源失效与交叉核对记录；明确「供给不足」是否成立。
3. **画像流失**：各步累计与步间流失，逐人定性原因（访谈/追访证据编号）。
4. **依据理解与信任**：事件 match_basis 率 **+** 模块 2 人工复述率/误认率（两套数并列），误认逐人证据。
5. **关注与推进动作**：各类去重人数与率；满窗口未行动人数及追访原因结构。
6. **北极星**：分母/分子/率、观察中人数；与模块 0 假设（40%）的对照写成「验证/未验证/不足以判断」，不写成达标与否的业绩结论。
7. **公告维护人时**：总量、每在报岗位人时、来源巡检与纠错处理耗时占比。
8. **高影响错误**：逐条列出（编号、严重度、影响、处置状态）；未关闭项不得在结论中省略。
9. **人工×事件对照**：抽样比例、三类差异计数与处理、被标「数据不完整」的指标。
10. **结论**：A/B/C/D（可带条件组合）+ 台账证据编号 + 具体行动清单（指向模块）+ 样本量与流失原因说明 + 局限（0 在报窗口、选择偏差、追访无应答）。
11. **无真实结果不编造结论；不把「接近目标」写成「基本达成」；演示/种子数据一律不得出现在本报告。**

## 八、红线清单

- 不写「已上线」：闸门未全绿前产品内对外表述仍为受邀/预筛，公开地址、备案、纠错处理人、迁移任一缺项即停。
- 不用演示/种子数据（demo/seed 分群）充当试用结论；员工账号单列。
- 不诱导用户对已截止/预告批次完成「报名」类动作凑指标。
- 不记录资格原文、证件信息、联系方式进事件与公开台账。
- 不在窗口未满、样本不足、事件未对账时给出四选一结论或扩量决定。
