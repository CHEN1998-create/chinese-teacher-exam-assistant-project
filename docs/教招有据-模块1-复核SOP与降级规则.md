# 教招有据 · 模块 1：官方招聘事件复核 SOP 与降级规则

- 版本：v1.0（2026-10-06）
- 适用范围：验证期首批监测地区 **浙江杭州（330100）/ 宁波（330200）**、学科 **语文**
- 配套台账：[教招有据-模块1-招聘事件台账.csv](./教招有据-模块1-招聘事件台账.csv)（3 条公告 / 4 个报考单元，UTF-8 带 BOM，36 列）
- 结构化镜像：`backend/src/matching/real-catalog.ts`（运行时事实源）、`backend/src/matching/coverage.ts`（覆盖事实源）
- 规则实现：`backend/src/matching/engine.ts`（规则版本 `kb-match-rules-1.2.0`）

---

## 0. 四条不可越过的底线

1. **官方事实 / 系统推断 / 用户确认 / 未知 四分清。** 公告与岗位表白纸黑字的才是「官方事实」；匹配结论是「系统推断」；画像内容是「用户确认」；官方没写的一律「未知」。
2. **缺信息 ≠ 不符合。** 官方未公布的内容（典型：预告批次的报名时间）登记到 `pendingItems`，禁止用「预计」「参考往年」「一般在 X 月」等措辞补一个日期。
3. **「暂未收录」≠ 当地无招聘。** 前台必须同时说清覆盖地区、最近核对时间与该结论的时间边界。
4. **演示数据与真实数据物理分离。** 演示目录 `catalog.ts`（example.gov.cn 占位）与真实台账 `real-catalog.ts` 通过 `dataset='demo'|'real'` 区分；真实记录未人工复核前不得进入「初步符合」主要推荐。

## 1. 台账记录结构（每行 = 一个报考单元）

一个公告（announcement）可含多个报考单元（unit，对应岗位表一行/一组岗位）。台账每行必须能独立追溯：

| 必备信息 | 字段/位置 |
| --- | --- |
| 官方原文 | 公告发布页 URL（政府域名）、公告标题、发布单位、发布时间、索引号（如有） |
| 岗位表位置 | 附件名 + 工作表/序号行 + **可直接下载的附件 URL** + 该行原文摘录 |
| 资格关键字段 | 学历、学位、专业、教师资格（含学段/普通话）、年龄、户籍/生源、招聘对象、用工性质 |
| 时间 | 报名起止、笔试/面试时间；官方未公布则留空并写入「待官方明确」 |
| 复核留痕 | AI 核对时间/核对人、人工复核状态、复核人、复核时间 |
| 版本关系 | 补充公告关系、当前版本号（v1/v2…）、生命周期（预告/在报/已截止/取消） |
| 投入度量 | 采集人时、复核人时（分钟） |
| 来源健康 | 来源失效记录（HTTP 状态、巡检时间、恢复时间） |

代码镜像中的对应关系：

- 公告/单元/条件/时间线：`RecruitmentAnnouncement / ApplicationUnit / Requirement / AnnouncementTimeline`（`backend/src/matching/types.ts`）
- 行级岗位表锚点：`ApplicationUnit.sourceRow: EvidenceAnchor`（附件 URL + `anchor` 文本 + `excerpt` 摘录）
- 证据状态：`EvidenceAnchor.state = 'official' | 'ai_extracted' | 'pending_review'`
- 复核状态：`announcement.reviewStatus = 'ai_reviewed_pending' | 'human_reviewed'`，配套 `reviewedBy / reviewedAt`
- 来源健康：`announcement.sourceHealth = { ok, checkedAt, failReason? }`

## 2. 标准复核流程（AI 初核 → 人工复核 → 发布）

### 2.1 AI 初核（联网采集，不落「已核对」）

1. 在监测来源清单（见 `coverage.ts` 的 regions/sources）内定位**公告栏目原文页**，记录 URL、发布时间、发布单位。
2. 下载公告中的岗位表附件，定位语文岗位行，记录：附件名、工作表、序号/行、下载 URL、行原文摘录。
3. 逐个抽取高影响字段（见 3.1），每个字段一条 `Requirement` + 一个证据锚点（URL + anchor + excerpt）。
4. 所有锚点 `state='ai_extracted'`，公告 `reviewStatus='ai_reviewed_pending'`、`reviewedBy/reviewedAt=null`；在台账登记 AI 核对时间与采集人时。
5. 时间字段规则：
   - 公告给了明确日期 → 原样登记（`YYYY-MM-DD`，不做时区/口语换算）；
   - 只说「初定 X 月，具体另行通知」→ 报名起止**留空**，把原话放进 `timeline.pendingItems`；
   - 无法访问附件 → 该字段不填值，先登记来源问题（见 4.3），不猜。
6. 初核完成后记录进入「真实监测记录」分区，前台明确标注「AI 初核 · 待人工复核」。

### 2.2 人工复核（唯一可把证据升为 official 的环节）

复核人逐条完成下列动作，全部通过才可升级：

1. **链接可达**：打开公告原文 URL 与岗位表附件下载 URL（政府域名、非转载、非第三方汇总站）。
2. **单位与批次**：公告发布单位、标题、批次与台账一致。
3. **行级锚点**：附件名 + 工作表 + 序号/行能定位到该行；该行学段/学科确为语文；人数一致。
4. **高影响字段逐字核对**：学历、专业、毕业/就业状态、教师资格、年龄五项与该行/公告原文逐字一致；有放宽条款的，放宽条件也要摘录。
5. **时间核对**：报名起止、笔试时间与公告一致；预告批次仍无后续通知的，保持留空。
6. **用工性质**：以公告原文表述为准（如「财政全额拨款事业编制」）；原文表述模糊无法确认编制/备案/员额时，按 4.2 降级，不自行归类。
7. **补充公告排查**：检查栏目是否已有补充/更正/延期/取消公告；有则先走版本流程（第 5 节）再复核。
8. 全部通过后：
   - 代码镜像：相关锚点 `state` 改 `'official'`，公告 `reviewStatus='human_reviewed'`、填 `reviewedBy/reviewedAt`；
   - 台账：人工复核状态改「已复核」，登记复核人、复核时间、复核人时；
   - 若该公告当前在报且所有闸门通过，它才会进入「初步符合」推荐。

任一高影响字段无法在官方原文中定位 → 该字段保持非 official，该公告**不得**升级为 human_reviewed；可整体复核通过但单条证据存疑时，在台账备注写明存疑点。

### 2.3 复核频率（新鲜度要求）

- 在报批次（未到报名截止）：**每 72 小时**至少复核一次官方源与高影响证据；
- 距报名截止 **≤72 小时**：提频到 **每 24 小时**一次；
- 预告批次 / 已截止批次：不按在报频率卡控，但预告批次在公告所称「初定」时间窗口前后须主动排查后续通知；
- 每次巡检更新所有相关 `checkedAt`；超期未核 → `evidence_stale` 闸门失败（见 3.2）。

## 3. 闸门与降级规则

匹配结果有 9 个闸门（`engine.ts` 的 `evaluateGates`），任一失败即 `isValidOpportunity=false`，不进推荐；卡片只展示闸门给出的失败理由（理由必须是人话、含时间/来源）。

### 3.1 高影响字段清单（无 official 证据不进推荐）

`HIGH_IMPACT_DIMENSIONS = education / major / graduate_status / teacher_cert / age`。

`evidence_not_reviewed` 闸门通过条件（三者同时满足）：

1. 每个高影响 `Requirement.evidence.state === 'official'`；
2. 若单元带 `sourceRow`，其 `state` 也必须为 `'official'`；
3. 公告 `reviewStatus !== 'ai_reviewed_pending'`。

### 3.2 九个闸门一览

| 闸门 code | 失败场景 | 前台/卡片表现 |
| --- | --- | --- |
| `subject_not_open` | 非验证期开放学科 | 不收录语文以外学科 |
| `registration_unconfirmed` | **报名起止日期缺失**（预告批次） | 「官方尚未公布具体报名时间，以官方后续通知为准」；不出现任何日期与倒计时 |
| `registration_closed` | 当前时间晚于报名截止 | 「X月X日 已截止」 |
| `out_of_scope_nature` | 用工性质不在收录范围（劳务派遣等） | 说明性质并导向官方原文 |
| `announcement_withdrawn` | 公告取消/撤回（`lifecycle='withdrawn'`） | 「公告已取消或撤回：查看官方留档与版本记录」 |
| `source_unavailable` | `sourceHealth.ok=false` | 展示巡检发现（如 HTTP 404）与巡检时间 |
| `no_official_source` | 公告级来源锚点非 official | 「缺少已核对的官方依据」 |
| `evidence_not_reviewed` | 高影响证据/行级锚点未人工复核，或公告仍为 AI 初核态 | 「记录尚待人工复核：先查看官方公告原文」 |
| `evidence_stale` | 在报且未截止的机会，官方源/高影响证据/sourceRow 中最旧 `checkedAt` 超 72h（临近截止超 24h） | 提示复核时间与阈值，不展示为「当前有效」 |

说明：`registration_unconfirmed` 失败时 `registration_closed` 恒为 passed——预告既不是「在报」也不是「已截止」，禁止互相冒充。`evidence_stale` 不约束预告与已截止记录。

### 4. 专项降级口径

### 4.1 预告批次（如鄞州 2026-07-31 公告）

- 报名时间留空 → `registration_unconfirmed` 失败；
- AI 初核态 → `no_official_source` + `evidence_not_reviewed` 失败；
- 卡片进入「真实监测记录」分区，展示公告与岗位表链接，标注「AI 初核待复核」；
- 监测动作：在公告所称「初定 2026 年 9 月」起持续排查报名通知；一旦官方发布报名时间，按**新版本追加**（v2，sourceKind='supplement'），填时间线、重新走复核，旧 v1 保留。

### 4.2 用工性质不明

- 公告原文出现「事业编制 / 财政全额拨款（补助）事业编制 / 备案制 / 员额制 / 控制数 / 聘用合同制」等表述时，`employmentNature.officialName` **逐字使用官方措辞**；
- 原文不能确认性质的，显示「用工性质以官方公告为准（待确认）」，并让 `out_of_scope_nature` 或人工复核流程兜住，不得为了凑推荐而归类成事业编。

### 4.3 来源失效与恢复

1. 巡检发现公告页/附件无法访问（404/403/超时/域名变更）：
   - 登记 `sourceHealth = { ok:false, checkedAt, failReason:'公告页 HTTP 404' }`，台账「来源失效记录」列写明现象与巡检时间；
   - `source_unavailable` 闸门失败，该机会立即退出推荐，但**数据与版本链原样保留**；
2. 同步排查：是否为站点改版换链（找到新 URL 则更新锚点并重新计时复核）、是否公告被撤回（改走取消流程）；
3. 恢复：下一次巡检确认可访问后改回 `ok:true` 并更新 `checkedAt`，无需改任何业务数据；若证据已超新鲜度阈值，则先补复核再恢复推荐。

### 4.4 取消（withdrawn）

- 官方明确取消招聘：公告 `lifecycle='withdrawn'`，记录 `withdrawnAt / withdrawReason`（引用官方原话）；
- 不删除公告、不删除版本、不删除关注关系；卡片文案改为取消并保留官方链接留档；
- 已关注用户的提醒按既有通知机制处理，不得再推送报名/考试类提醒。

## 5. 版本规则：只追加，不改写

- 任何**官方事实变更**（延期、报名时间公布、条件更正、招聘人数调整、取消）一律新增版本（versionNumber+1），`sourceKind` 取 `supplement / correction`，旧版本标记 `supersededAt` 后**原样保留**；
- 推荐只取 `currentVersion`（版本号最大者，见 `engine.ts`），历史版本通过详情页「历史版本」与台账「补充公告关系」可追溯；
- 审核留痕能力（提交/审批/发布）复用 `backend/src/announcements/domain.ts`：`publishVersion` 只追加、`assertCanApprove` 控制状态流转、`HIGH_IMPACT_FIELDS` 为变更重点审查项；
- 不允许「原地修改 v1」——即使只改一个日期。文字错字修复若不影响事实结论，可在备注记录，但高影响字段的任何改动都必须新版本。

## 6. 人时记录口径

- **采集人时（AI/采集人）**：从打开来源栏目到完成初核登记（含下载附件、定位行、摘录、填台账、写镜像）的净分钟数；
- **复核人时（人工）**：复核人完成 2.2 全部动作的净分钟数，含打开链接、逐字核对、记录结论；
- 只记净工作时间，不记等待时间；按报考单元在台账中登记（当前 3 条样本：采集 20–25 分钟/单元，复核待发生）。

## 7. 前台展示约定（模块 1 范围）

1. 机会页 Hero 下方展示覆盖说明（`CoverageBanner`）：覆盖地区（杭州/宁波）、监测来源清单与各源最近核对时间、**当前 0 个在报语文岗位**、下一窗口提示（预计 11–12 月提前批 + 鄞州预告跟踪）、「暂未收录不代表当地无招聘」的边界声明、覆盖版本号。
2. 真实卡片独立分区「真实监测记录（杭州/宁波 · AI 初核待人工复核）」，与演示卡分区；每卡可直接打开「官方原文 ↗」「岗位表附件 ↗」；详情页含岗位表行级锚点、复核状态、时间线（预告显示「官方尚未公布具体报名时间」）。
3. 真实记录当前全部落在「不推荐」侧：鄞州=报名时间未定 + 待复核；杭州 4 月批/宁波 7 月批=报名已截止 + 待复核。有效机会计数不含这些卡片。
4. 所有时间相关文案都以 DTO 字段为准，前端不复制任何判定规则（`deadlineText` 对 `undefined` 的处理：`报名时间待官方通知`，不渲染任何推断日期）。

## 8. 验收方法（已自动化）

1. **3 条真实机会卡片 → 官方依据追溯**
   - 后端：`backend/src/matching/real-catalog.spec.ts`——断言 3 公告 4 单元、gov.cn 原文 URL、岗位表序号 1/5/6 与下载链接、各单元闸门失败原因、全部 `ai_extracted`；
   - 前端：真实卡片渲染「官方原文 / 岗位表附件」链接与「AI 初核待人工复核」标记，覆盖横幅显示 0 在报与 2026-10-06 核对时间。
2. **延期 / 取消 / 来源失效回放**：`backend/src/matching/acceptance-lifecycle.spec.ts`
   - 延期：v1（9/10 截止，带 `supersededAt`）保留在版本链，推荐只基于 v2（10/20 截止）且闸门全过；
   - 取消：`announcement_withdrawn` 失败、不进推荐，v1 与官方链接保留；
   - 来源失效：`source_unavailable`（含 HTTP 404 理由）失败且记录保留；巡检恢复 `ok:true` 后同一版本自动重新参与评估。
3. **新鲜度与预告降级**：`backend/src/matching/gates.spec.ts`——72h/24h 阈值、预告无日期、AI 初核不放行。
4. 手工复核三条样本时，按第 2.2 节逐项打勾；全部完成后把镜像中的锚点/复核状态升级并在台账签字（登记复核人/时间/人时），届时真实在报批次才允许进入「初步符合」。
