### 1.3 已发现的双轨技术债（本稿不还债，只隔离）

侧边栏「我关注的机会」块读的是**本地** `useCurrentExamTarget()`（`kb_exam_targets`，v5.2「考试目标」概念）；而「主要目标」真值在**服务端** `role='primary'`（goals 接口、`primaryTargetUnitId`）。两者并行存在。模块 3 实施时该区块改为读服务端主要目标，本地 `kb_exam_targets` 保留给备考管线独占使用——**不合并库表、不做数据迁移**，只统一展示口径（见迁移方案第 4 节）。

## 二、新一级导航：机会 / 日程 / 我的

### 2.1 三分区职责

| 一级入口 | 职责 | 包含 | 明确不放 |
| --- | --- | --- | --- |
| **机会** | 找、看、判断要不要关注 | 覆盖说明（模块 1 CoverageBanner）、四档列表、真实监测记录、机会详情（依据/缺项/下一步、官方原文与岗位表行）、关注与设主要目标 | 报名材料清单、备考任务 |
| **日程** | 盯住**下一项报考动作**、材料与官方节点 | 首屏仅 1 张「下一件不能错过的事」（必须/建议/知道三档）、关注机会时间线、待官方通知节点、（模块 6 后）材料清单与官方咨询记录入口 | 备考学习任务 |
| **我的** | 与「我这个人」有关的设置与记录 | 主要目标卡（含**备考次级入口**）、我的画像、通知与提醒设置、我的资料、我的纠错与处理进度、隐私与数据、账号与退出 | 机会发现、时间线浏览 |

### 2.2 备考为什么降为次级、放在哪

- 规则：**只有已设主要目标后才出现「备考」入口**——与现有 `lib/goals/domain.ts` 的 `StudyGateState` 三态（`no_primary / exam_unverified / ready`）对齐，不新增门禁概念。
- 入口位置（两个，都是次级）：
  1. **我的 → 主要目标卡**：有 primary 时卡尾显示「进入备考 →」（直达 `/study`，未确认考试内容时落到现有 `exam_unverified` 页）；无 primary 时显示「去机会里选一个主要目标」，**不出现备考入口**。
  2. **机会详情页**：设为主要目标成功后的轻提示里给「稍后可在『我的』进入备考」。【待模块2证据校准：是否还需要在日程页底部放备考入口；默认不放】
- `/study` 路由、页面、全部 `kb_*` 备考数据、`tgt-${unitId}` 派生规则**原样保留**；旧链接 `/today`、`/plan` 仍 307 到 `/study`。

### 2.3 手机页面地图（底部三 Tab，高 64px 触控规格沿用 BottomNav）

```
┌─ 机会 Tab ────────────────┐
│ 覆盖条：杭州/宁波·0在报·核对时间 │
│ 初步符合 → 需补信息 → 人工确认 │
│ 真实监测记录分区（AI初核标）    │
│ 已截止/不符合（折叠）          │
├─ 详情（推入，保留 Tab 高亮机会）┤
│ 结论→下一步→依据与不确定项     │
│ 官方原文/岗位表行/核对时间      │
│ [关注] [设为主要目标]         │
└───────────────────────────┘
┌─ 日程 Tab ────────────────┐
│ 下一件不能错过的事（唯一主按钮） │
│ 必须 / 建议 / 知道 分组        │
│ 待官方通知（不显示臆造日期）     │
│ 关注机会时间线（按机会折叠）     │
└───────────────────────────┘
┌─ 我的 Tab（新增 /me）───────┐
│ 主要目标卡（有：进入备考；无：去选择）│
│ 我的画像（完成度）[查看/修改]  │
│ 通知与提醒 [未读数小红点]      │
│ 我的资料                     │
│ 我的纠错（提交记录+处理进度）   │
│ 隐私与数据 / 账号与退出        │
│ （工作人员）运营后台入口       │
└───────────────────────────┘
```

- `/opportunities/[unitId]` 等二级页在手机上为推入页：底部 Tab 保留、原分区高亮保留（`isNavActive` 前缀匹配已支持）。
- 无外壳的访客流（`/`、`/onboarding`、`/preview`）不显示 Tab，维持现状；模块 4 做免登录预筛时保留此边界。

### 2.4 桌面页面地图（左侧固定栏 256px 规格沿用）

```
┌ 侧边栏 ────┬──────────────────────────────┐

│  运营后台   │ 设置 / 资料：保留现有页面，/me 卡片链接进入  │
│ 头像+铃铛   │                                              │
└───────────┴──────────────────────────────────────────────┘
```

\* 侧边栏区块由「我关注的机会（本地考试目标）」改为「**主要目标（服务端 role=primary）**」；无主要目标时保留虚线引导卡，文案改为「还没选定主要目标」→ `/opportunities`。

### 2.5 三类角色看到的导航

| 角色 | 一级 Tab | 特殊处理 |
| --- | --- | --- |
| 访客（未登录） | 维持无外壳流程（首页→`/onboarding`→`/preview`），页面内用同构三段式引导而非真 Tab（模块 4 范围） | 登录后访客草稿（`kb_guest_profile_v61`）按现有 `activeProfile.ts` 合流；放开 RequireAuth 不属模块 3 |

| 工作人员 | 同上 + 侧边栏「运营后台」 | 现有条件（`STAFF_ROLES` 且非演示）不变；后台布局不动 |

## 四、界面文案与技术字段的边界（本模块铁律）

1. **只改用户能看见的中文文案，不改任何既有技术字段名**：

| 用户看到（界面文案） | 技术字段（保持不变） |
| --- | --- |
| 主要目标 | `FollowedOpportunity.role = 'primary'`、`primaryTargetUnitId`、事件 `primary_target_set` |
| 备选目标 | `role = 'backup'` |
| 已关注（仅关注） | `role = null` |
| 考虑中/准备报名/已报名/已放弃/已关闭 | `status = considering/preparing/registered/abandoned/closed` |
| 我的画像 | `user_profiles` / `kb_guest_profile_v61` / `kb_profile_supplement_v61` |

2. 新增 `GOAL_ROLE_LABELS`/`FOLLOW_STATUS_LABELS` 集中放在 `lib/ia/labels.ts`，页面不得硬编码枚举中文。
3. 侧边栏区块切到服务端 goals 后，UI 不再出现「考试目标」字样，统一为「主要目标」；`kb_exam_targets` 的代码、类型、键名全部保留。
4. **改字段名/键名前必须先走迁移方案**；本轮 IA 调整不触发任何字段改名，不执行迁移。
