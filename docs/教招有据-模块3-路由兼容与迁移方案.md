## 3. 字段与存储迁移方案

### 3.1 本轮结论：**零字段改名、零键变更、零库表迁移**

模块 3 只是入口与聚合层调整。界面文案与技术字段按下表映射，代码内枚举/键名一律不动：

| 界面文案 | 技术字段（不变） |
| --- | --- |
| 主要目标 / 备选目标 / 已关注 | `FollowedOpportunity.role`：`primary` / `backup` / `null` |
| 考虑中/准备报名/已报名/已放弃/已关闭 | `FollowedOpportunity.status` 五枚举 |
| 我的画像 | `user_profiles`、`kb_guest_profile_v61`、`kb_profile_supplement_v61` |
| 提醒开关 | `FollowedOpportunity.remindersMuted`、日程 `mutedUnitIds` |
| 备考目标（仅备考管线内部） | `kb_exam_targets` / `ExamTarget.isCurrent` |

因此：**无 Prisma migration、无 localStorage 版本号升级、无数据回填脚本。**

### 3.2 数据源切换（不是迁移）：侧边栏主要目标区块

| 项 | 现状 | 切换后 |
| --- | --- | --- |
| 数据源 | 本地 `useCurrentExamTarget()`（`kb_exam_targets`） | 服务端 goals（`primaryTargetUnitId` + goals 列表） |
| 旧数据处理 | — | `kb_exam_targets` **原样保留**，继续被 `/study` 计划管线读写；不删除、不合并、不双写 |
| 一致性风险 | 本地目标与服务端 primary 可能不一致 | 展示层只认服务端 primary；本地 isCurrent 仅影响备考管线。U9 场景由 `tgt-${unitId}` 稳定 id 保证历史计划可恢复 |
| 回滚 | — | 还原 Sidebar 区块组件即可，无数据回滚动作 |

### 3.3 未来若确需改字段/键名（本轮不执行，仅立规矩）

任何技术字段改名须独立出方案并满足：
1. **双读期**：读取侧同时兼容新旧键/枚举，类型用联合态；不得只写不读旧值。
2. **只追加不覆写**：服务端沿用 `publishVersion` 式只追加原则；本地键升版本号（如 `kb_xxx_v62`），保留旧键 N 个版本，提供一次性迁移函数并在启动时幂等执行。
3. **迁移函数纯函数化 + 单测**：输入旧结构输出新结构，覆盖缺字段/脏数据；失败不得清空旧键。
4. **灰度与回滚**：特性开关控制；回滚只需关开关，旧键仍在。
5. 涉及后端枚举（如 `role/status`）须先加新值、双端兼容后再停用旧值，并配 Prisma migration 评审。

## 4. 旧状态不丢核对单（回归测试清单）

| 存量状态 | 核对方法 | 通过标准 |
| --- | --- | --- |
| 关注列表 | 造 considering/preparing/registered/abandoned/closed 各 1 条 | 模块 3 后列表条数、状态、`statusHistory` 完全一致 |
| 主要/备选 | 1 primary + 2 backup | 我的页主卡 = primary；backup 在机会页标记不变；U9 切换后历史可恢复 |
| 提醒静音 | 静音 1 个关注 | 日程页静音状态保留；通知仍不产生 |
| 日程节点 | 含 pending（待官方通知）与 past 节点 | 三档分组、待通知文案、过去节点展示不变 |
| 备考计划族 | `kb_plans/kb_daily_plans/kb_task_feedbacks/kb_plan_adjustments/kb_weekly_reviews/kb_ability_baselines` 有存量 | 从 /me 进 `/study`，计划与反馈历史完整；周复盘、重排记录可查 |
| 备考目标 | `kb_exam_targets` 含 isCurrent 与 `tgt-*` 派生目标 | 数据不删不改；重新设同一主要目标后复用 |
| 考试内容确认 | `kb_exam_content_confirmations` 绑定 versionId | 公告版本变更后旧确认失效的行为不变 |
| 画像 | 登录用户 profile + 访客草稿 + 补充项三份数据 | 编辑模式保存后三份数据合流规则与现状一致 |
| 治理数据 | 纠错、通知、通知偏好、删除申请、撤回日志 | /me 新入口看到的条数与原入口一致；后台队列不变 |
| 资料 | `kb_materials`、`kb_material_diagnoses` | /materials 与备考内引用均正常 |

## 5. 实施顺序与回滚

1. 先做 labels 映射 + `nav.ts` 常量（纯函数与单测先行）。
2. 新增 `/me` 三个页面（不删任何旧入口）。
3. 切换 Sidebar/BottomNav 数据源与导航项；`/study` 改返回链接。
4. AppShell 白名单、`/settings#privacy`、画像编辑模式。
5. 第 2 节矩阵全部走通 + 全量前端测试后，才合并。
- 每步独立可回滚；任一步失败不影响旧 IA（`/study` 始终在、middleware 始终在）。
