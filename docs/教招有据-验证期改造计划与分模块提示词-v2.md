# 教招有据｜验证期改造计划与分模块提示词（v2）

更新时间：2026-10-06  
定位：产品名为“教招有据”；“验证版”是阶段标识，不是产品全称。  
使用方式：先执行共用提示词，再逐轮复制一个模块提示词；上一模块通过验收后才进入下一模块。  
版本关系：本文件取代《v7.0-验证期改造计划与分模块提示词》的执行建议，旧文件保留作历史记录。v7.0 PRD 是目标，v6.1 PRD 与现有代码是实现基线；两者不能混称“已上线”。

## 一、目标澄清

**原始需求**：把产品名改为“教招有据”，重新优化验证期改造计划和按顺序执行的分模块提示词，提交一份包含更名的新版本。  
**显性目标**：统一名称、梳理先验证后改造的步骤、给每个模块可复制的实施提示词。  
**隐性期望**：避免继续堆功能；用真实官方机会和真实用户行为判断“可解释资格预筛能否推动报考行动”。  
**一句话目标**：让目标用户从可信的语文教师招聘机会出发，看懂资格依据，并在 7 日内采取可记录的报考下一步。

| 需要的上下文 | 当前状态 | 影响 |
|---|---|---|
| 技术与代码 | 已知：Next.js 前端、NestJS 后端、PostgreSQL；根目录与前后端分别有 Git 状态 | 能复用现有匹配、公告版本、关注与日程 |
| 首批地区、官方机会供给 | 待产品负责人确认 | 决定能否形成真实且未过期的推荐 |

| 受邀试用地址与国内普通网络可达性 | 待确认；现有境外演示地址不能当作真实受邀环境 | 决定 20—50 人试用能否启动 |
| 商标、域名、账号名称占用 | 待正式核查 | 决定能否将“教招有据”作为对外长期品牌 |

## 二、信息梳理与产品名称规则

### 已知与限制

- v7.0 PRD 的 P0 是官方招聘机会、逐项资格判断、报考推进、公告变化和可信度；完整备考计划为 P1。
- 当前页面仍有 v6.1 的“机会／日程／备考”主导航、备考导向文案和本地浏览器事件；它们是改造对象，不是 v7.0 已完成的证据。
- 当前已将“教招有据”写入首页、浏览器标题、登录页、侧边栏、移动端兜底标题、管理端标识和 v7.0 PRD 页眉；尚未完成全站品牌与历史文档边界审计。
- 初轮只服务语文教师招聘；“全国”是长期方向，不代表当前全国岗位覆盖。
- 产品只能提供**有官方依据的资格预筛**，不能承诺最终报考资格；“有据”指证据可追溯，不指结论必然正确。

## 三、数据摸底与验证口径

| 项目 | 当前可确认状态 | 本轮需要补齐 |
|---|---|---|
| 研究线索 | 网络样本和官方批次研究已形成问题假设；不是活跃用户行为基线 | 保留研究来源、样本边界 |
| 画像完成率、结果理解率、关注率 | 无可信真实受邀试用基线 | 人工验证先记逐人数据；后续服务端采集 |
| 7 日有效目标推进率 | v7.0 PRD 定义目标为 ≥40%，尚未实测 | 明确分母、窗口、去重、排除项，做人工对账 |
| 机会采集与复核成本 | 未建立稳定台账 | 每条事件记录采集、复核、变更人时 |
| 现有实现 | 有匹配、公告版本、关注、日程与演示机会；缺完整报名材料和官方咨询闭环 | 用真实机会和关键异常场景校验 |
| 竞品/行业基准 | 尚无可直接类比的可信同口径数字 | 不用竞品转化率代替本产品目标 |

**建议执行口径，需在模块 0 由负责人确认**：分母为完成基础画像、首次看到至少一个真实、未过期、在地域范围内且无已知明确不符合项机会，并已满 7 日观察期的受邀用户；从首次看到有效机会起算。分子为其中 7 日内关注至少一个该类机会，且对机会完成至少一个有效推进动作的去重人数。有效动作按 v7.0 PRD：补充影响资格判断的信息并使结果更新、标记准备报名、完成至少一项报名材料、进入官方报名入口后标记已报名、设为主要目标。只浏览、只看公告、只关注、仅做备考任务不计入。演示机会、员工、测试账号不计入。没有有效机会的用户不进入这个分母，但必须单列“有效机会获得率”，避免分母筛选掩盖供给不足。

PRD 中的 10 秒理解 ≥80%、画像完成 ≥70%、关注 ≥60%、7 日推进 ≥40% 都是**验证假设**，不是当前业绩或行业标准；10—15 人只用于发现问题和决定方向，不用于宣称稳定转化率。

每个模块只交付一组可验收产物；负责人可先并行准备素材，但核心链路按下表顺序验收。

| # | 子任务 | 输出物 | 完成标准 / 验证 | 负责／协作 | 依赖 | 状态 |
|---|---|---|---|---|---|---|
| 0 | 统一名称、范围和指标口径 | 品牌清单、v7/v6 差异表、指标字典 | 用户可见旧品牌已盘点；每项 P0 与指标口径有出处 | 产品／设计、前后端 | 无 | 已完成（2026-10-06，见 [`教招有据-模块0-品牌清单与版本决策记录.md`](./教招有据-模块0-品牌清单与版本决策记录.md)；名称占用核查仍待启动） |

| 2 | 做 10—15 人人工服务验证 | 招募、访谈、逐人 7 日记录与复盘 | 看懂依据与下一步；记录真实动作、错误和人时 | 产品／运营 | 1 | 待开始 |
| 3 | 收敛信息架构和导航 | 页面地图、导航与旧路由兼容表 | 手机、桌面三条主路径走通；历史数据不丢 | 设计／前端 | 2 | 待开始 |
| 4 | 优化首页与渐进画像 | 首页、问答、失败/空态 | 5 位非设计参与者独立完成并记录耗时、流失 | 设计／前端 | 3 | 待开始 |
| 5 | 改造列表和证据详情 | 四档结果卡、详情、依据与异常态 | 用户能说清一条依据、一条不确定项及下一步 | 设计／前后端 | 4 | 待开始 |
| 6 | 打通关注至报名推进 | 材料清单、官方咨询、状态与日程 | 一条真实机会从关注走到材料或报名行动 | 前后端／运营 | 5 | 待开始 |
| 7 | 处理公告变化与纠错 | 版本差异、影响说明、可信状态 | 延期/取消/条件变化/失效端到端回放 | 后端／运营、前端 | 1、6 | 待开始 |
| 8 | 建立真实试用指标与上线门槛 | 服务端事件、看板、隐私与访问检查 | 人工样本可对账；普通网络真实地址可访问 | 前后端／产品 | 5—7 | 待开始 |
| 9 | 完成 20—50 人受邀试用 | 7 日结果与继续/收缩/停止决策 | 至少完整观察 7 日；护栏问题复盘 | 产品／运营 | 0—8 | 待开始 |

**关键路径**：名称与口径 → 可持续的真实机会 → 人工验证 → 按发现改核心流程 → 真实埋点和试用环境 → 7 日受邀试用。模块 3—8 的方案可提前草拟，但不能越过模块 2 的证据直接大规模实施。

**里程碑**：

1. M1（验证问题）：模块 0—2；至少有用户能复述依据、出现真实关注或报考推进，没有已知高影响误判。若未达到，先修供给/规则或缩窄人群。
2. M2（可用原型）：模块 3—7；至少 5 人可独立完成“画像 → 理解结果 → 关注 → 下一步”，关键异常有处理方式。
3. M3（受邀试用）：模块 8—9；真实地址可用、岗位有人复核、事件可对账、没有已知高影响错误，才邀请 20—50 人。

排期仅作容量估计：模块 0—1 可先预留 3—5 个工作日；模块 2 至少 7 日观察；模块 3—8 再按验证发现估算；模块 9 再覆盖完整 7 日。地区、样本与复核人未定时不作日期承诺。

## 五、风险预判与验收清单

| 风险 | 影响 | 预防 / 停止条件 |
|---|---|---|
| 真实岗位少或已过期 | 有效机会率低，指标失真 | 先缩首批地区；无有效机会不得把演示岗位冒充真实推荐 |
| 资格误判与来源过期 | 用户可能误报、错过报名 | 高影响字段复核；来源失效或冲突即降级；已知高影响错误时暂停扩量 |
| 名称“有据”被理解为官方保证 | 信任边界混淆 | 固定展示官方来源、核对时间、预筛声明；名称测试询问误解 |
| 演示行为混入真实指标 | 夸大转化 | seed/live、测试/真实、受邀/演示分层和服务端去重 |
| 个人敏感资料收集过度 | 隐私与安全风险 | 只收最少条件；证件号不采集；埋点不含资格原文或身份信息 |
| 旧导航/数据被更名顺带破坏 | 回归成本高 | 更名只改可见品牌；路由、字段、存储 key 单列迁移 |
| 国内受邀访问失败 | 无法做真实试用 | 真实域名、普通网络、不同设备验收后再邀请 |

**最终验收清单**：品牌一致且无官方背书暗示；真实覆盖透明；四档状态与证据一致；关注后有材料和下一步；公告变化保留版本；隐私与权限边界清楚；服务端指标可手工复算；7 日真实用户行为与错误复盘完成。未取得样本或真实环境时，把相应结论标为“待验证”，不能写“已达成”。

改造 /preview、/opportunities 和报考单元详情的信息层级，不在本轮加入报名材料。卡片首层只展示报考单元、用工性质/学段、人数、截止时间、四档状态、一条关键依据或风险、一个下一步；长证据按需展开。详情按“结论 → 下一步 → 关键依据与不确定项 → 官方原文/岗位表位置 → 核对时间与变化”组织，分清事实与推断。对初步符合、需补信息、人工确认、明确不符合以及未覆盖、过期、来源失效、空结果分别处理。交付四档与异常态样例。验收：用户可说清一条依据和一条不确定项，不能把缺信息判为明确不符合。
~~~

### 模块 6｜关注、材料与报名推进

~~~text
以一条真实机会为样板，把关注后的行动串成“补信息/官方确认 → 材料准备 → 官方报名入口 → 已报名”。按公告生成最小材料清单，逐项写来源、适用人群、待办/完成状态；提供官方联系信息与可复制的咨询问题模板，用户自行记录咨询结果但不把它变成官方事实。日程首屏只突出一个当前最重要动作；每个状态一个主按钮，失败和重复提交可恢复。交付前后端最小闭环及数据兼容说明。验收：真实机会从关注推进到至少一个可核实动作，跨设备恢复、未登录转登录和失败重试不丢状态。
~~~

### 模块 7｜公告变化与可信状态

~~~text
复用现有公告版本机制，处理补充公告、延期、取消、资格条件变更和官方来源失效。把“旧值 → 新值 → 对当前用户的影响 → 下一步”关联原招聘事件和已关注机会；保留旧版、重算必要的资格与日程、只通知受影响用户。来源失效、字段冲突、待审核要降级为可理解的可信状态；时间未定就写“待官方通知”。交付变更与纠错回放脚本。验收：延期、取消、条件变化、来源失效四类场景端到端通过，不重复通知、不把未核实字段写成官方结论。
~~~

### 模块 8｜指标、隐私与试用门槛

~~~text
审计现有浏览器事件和后端持久化，按模块 0 确认口径建立受邀试用必需的服务端事件、用户/机会去重和 7 日看板。单列有效机会获得率、画像各步、依据理解、关注、补信息导致结论变化、材料完成、准备报名、进入官方报名入口、已报名和主要目标；seed/live、员工/真实、演示/受邀分离。事件不含资格原文或证件信息。做手算样本对账，覆盖未满 7 日、重复点击、取消关注、跨设备和空样本。另核对真实受邀地址、账号权限、普通国内网络、岗位复核人和纠错处理人；缺项就停止邀请，不写“已上线”。交付指标字典、看板和发布前检查表。
~~~

### 模块 9｜受邀试用与下一轮决策

~~~text
只有模块 0—8 的发布门槛全部通过，才邀请 20—50 名目标用户完成至少一个完整 7 日窗口。每天记录机会供给、画像流失、依据理解、关注、各类推进动作、7 日有效目标推进率、公告维护人时与高影响错误，并追访未行动者。与模块 2 的人工记录对照，解释样本不足、供给不足和事件缺失，不仅展示比例。交付“继续聚焦资格判断／收缩地区或人群／先修数据与信任／再考虑 P0.5 与 P1”的决策报告；没有真实结果不编造结论，也不因只接近目标就自动扩量。
~~~
